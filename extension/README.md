# Experiment Reproduction

This document explains how to reproduce the planner experiments. All variants use the same environment, datasets, Push-T evaluation setup, and pretrained DINO-WM checkpoint. Only the planning objective changes.

## Required Checkpoints

Two checkpoint types are used.

### DINO-WM checkpoint

The pretrained DINO-WM checkpoint is required for latent encoding and world-model rollout.

Expected files:

```bash
dino_wm/checkpoints/outputs/pusht/hydra.yaml
dino_wm/checkpoints/outputs/pusht/checkpoints/model_latest.pth
```

These are external assets and are not generated by the planner.

### Feasibility checkpoint

The learned DSM feasibility model is trained separately and loaded only when feasibility is enabled.

Example:

```bash
checkpoints/transformer_sigma_delta.pt
```

When running without feasibility, use:

```bash
--feasibility-enabled false
--feasibility-checkpoint None
```

## Environment

Use the same environment as the reproduction experiments:
```bash
cd reimplementation
conda env create -n dl2 -f environment.yml
conda run -n dl2 python -m pytest
```
All planner modes use this same environment.

## Main Entry Point

Planner experiments are launched with:

```bash
python -u -m nicky_dl.examples.dino_oracle_demo_copy
```

Important arguments:

```bash
--raw-horizon {25,50,80}
--dynamics-mode {none,soft,alm,penalty,rollout}
--feasibility-enabled {true,false}
--lambda-feasibility VALUE
--lambda-dynamics VALUE
--lambda-transition VALUE
--feasibility-checkpoint PATH
--num-episodes N
```

## ALM Dynamics

This is the original hard-constrained latent-collocation planner. It optimizes both latents and actions while enforcing DINO-WM dynamics with an Augmented Lagrangian constraint.

```bash
python -u -m nicky_dl.examples.dino_oracle_demo_copy \
  --num-episodes 100 \
  --raw-horizon 50 \
  --dynamics-mode alm \
  --lambda-dynamics 10.0 \
  --feasibility-enabled false \
  --lambda-feasibility 0.0 \
  --lambda-transition 0.0 \
  --lambda-anti-stillness 0.0 \
  --min-action-norm 0.0 \
  --feasibility-checkpoint None
```

## Soft Dynamics Penalty

This replaces the ALM constraint update with a fixed-weight DINO-WM dynamics penalty.

```bash
python -u -m nicky_dl.examples.dino_oracle_demo_copy \
  --num-episodes 100 \
  --raw-horizon 50 \
  --dynamics-mode soft \
  --lambda-dynamics 10.0 \
  --feasibility-enabled false \
  --lambda-feasibility 0.0 \
  --lambda-transition 0.0 \
  --lambda-anti-stillness 0.0 \
  --min-action-norm 0.0 \
  --feasibility-checkpoint None
```

## Rollout Planning

In rollout mode, the planner optimizes only the action sequence. The latent trajectory is generated recursively by DINO-WM, so dynamics consistency is enforced by construction.

```bash
python -u -m nicky_dl.examples.dino_oracle_demo_copy \
  --num-episodes 100 \
  --raw-horizon 50 \
  --dynamics-mode rollout \
  --lambda-dynamics 0.0 \
  --feasibility-enabled true \
  --lambda-feasibility 0.01 \
  --lambda-transition 0.0 \
  --lambda-anti-stillness 0.0 \
  --min-action-norm 0.0 \
  --feasibility-checkpoint  YOUR_CHECKPOINT
```

## Feasibility-Only Planning

This enables the learned DSM feasibility prior without using the ALM dynamics constraint.

```bash
python -u -m nicky_dl.examples.dino_oracle_demo_copy \
  --num-episodes 100 \
  --raw-horizon 50 \
  --dynamics-mode none \
  --lambda-dynamics 0.0 \
  --feasibility-enabled true \
  --lambda-feasibility 0.01 \
  --lambda-transition 0.0 \
  --lambda-anti-stillness 0.0 \
  --min-action-norm 0.0 \
  --feasibility-checkpoint YOUR_CHECKPOINT
```

## Running Multiple Horizons

Supported raw horizons are:

```bash
25 50 80
```



## Notes

- All modes use the same Push-T environment and DINO-WM checkpoint.
- The feasibility checkpoint is only required when `--feasibility-enabled true`.
- `--num-episodes` controls how many eligible evaluation episodes are used.
- For all available episodes without changing code, set `--num-episodes` to a number larger than the eligible set.
- `--feasibility-checkpoint` is not included in the repo because of its size
- `--raw-horizon` is the environment horizon before conversion to macro-actions. In Push-T, one macro-action contains five consecutive 2D primitive actions.
- If disk quota is limited, write logs, checkpoints, and generated datasets to scratch instead of the home directory.
- Avoid duplicate logging by either using `#SBATCH --output/--error` or manual `> file.out 2> file.err` redirection, not both for the same stream.
